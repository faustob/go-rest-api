**Outstanding (5):**
- ⚠ qr-endpoint-env-driven (`cmd/otel.go`:4): Hardcoded OTLP endpoint "localhost:4317" — wrong in every real deployment. — _Read the endpoint from OTEL_EXPORTER_OTLP_ENDPOINT / config instead of a literal._
- ⚠ qr-not-a-noop (`cmd/server.go`): SaturationMiddleware and FlowMiddleware are defined in otel_middleware.go but are never wired into the chi router in main(). As a result the flow.outcomes/flow.duration metrics and the activeRequestCount driving http.server.active_requests are never updated at runtime. — _Register the middleware via router.Use(SaturationMiddleware) and router.Use(FlowMiddleware) in main()._
- ⚠ qr-not-a-noop (`cmd/otel_middleware.go`): RecordAuthAttempt and authAttemptCounter are registered but RecordAuthAttempt is never called from the JWT validation path, so the auth.attempts counter never emits any data. — _Invoke RecordAuthAttempt with allowed/denied outcomes inside the JWT validator middleware, or remove the unused auth metric._
- ⚠ general (`cmd/otel.go`): The http.server.worker_pool.size observable gauge reports int64(defaultPort) (8000), a hardcoded and semantically wrong value for a worker-pool size, producing misleading saturation data. — _Observe a real worker-pool bound (e.g. runtime.GOMAXPROCS(0)) or remove the gauge._
- ⚠ qr-preserves-behavior (`cmd/server.go`): initOtel is called after all routes are configured but the OTLP gRPC exporters use insecure defaults with no configured endpoint fallback; with telemetryCollection 'none' there is no collector on localhost:4317, so exporter creation/export will fail. This is non-blocking since errors are logged and the server still starts, but no telemetry is emitted. — _Document/guard the required collector endpoint, or gate OTel init behind an env flag._
