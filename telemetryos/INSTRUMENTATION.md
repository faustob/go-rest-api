**Auto-fixed during review (7):**
- qr-not-a-noop (`pkg/telemetry/otel.go`): SetupOTelSDK builds and registers only a TracerProvider; it never creates or registers a MeterProvider via otel.SetMeterProvider. Consequently otel.Meter(meterName) in instruments.go resolves to the default no-op meter and none of the custom counters/histograms/gauges emit any metrics at runtime.
- qr-preserves-behavior (`pkg/telemetry/validation.go`): RecordValidationStep starts a span with validationTracer.Start(ctx, ...) but discards the returned context (assigns to _), so the validation span is not propagated. It is created and immediately ended with no child work, and because no parent HTTP span exists on the request context (the SDK only has a tracer via otelhttp), the intended nesting under the request flow does not occur.
- general (`cmd/server.go`): The file uses http.Handler in the otelhttp middleware closure but the import block does not include "net/http"; the net/http package is not imported in cmd/server.go.
- general (`cmd/server.go`): otelhttp.WithServerName is not a valid otelhttp option in this contrib version; the option for setting the server name is not exposed this way, which will fail to compile.
- qr-not-a-noop (`pkg/telemetry/otel.go`): The MeterProvider is created with sdkmetric.NewMeterProvider() with no reader/exporter configured. A MeterProvider with no reader collects no metrics and exports nothing, so all the Int64Counter/Histogram/ObservableGauge instruments recorded in middleware.go and validation.go emit to nowhere.
- qr-preserves-behavior (`pkg/telemetry/middleware.go`): statusRecorder embeds http.ResponseWriter but does not implement http.Flusher, http.Hijacker, or io.ReaderFrom, so wrapping every request drops those optional interfaces from the writer chain. This can break streaming/SSE, connection hijacking (websockets), and efficient copies for any handler that type-asserts the ResponseWriter.
- qr-preserves-behavior (`pkg/telemetry/middleware.go`): In the slow-request branch, span.SetAttributes is called on the span from context when rec.status >= 500 without checking span.IsRecording(); if no real span is in context this operates on the no-op span (harmless) but the attribute-setting is outside the IsRecording guard used above, making the intent inconsistent.
