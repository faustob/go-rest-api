Since this middleware sits above the router's own route matching and otelhttp rewraps the context, the chi.RouteContext obtained here is nil (chi installs its context in its own ServeHTTP, which is the router itself, not reachable from a Use middleware's incoming context), so route is always "unmatched".

- qr-metric-naming (`pkg/telemetry/telemetry.go`): The new counter names http.server.request.count and http.server.auth.decisions mix the OTel semconv dotted domain with ad-hoc segments; semconv-style request counters are unsuffixed nouns and the auth counter invents an http.server.auth.* namespace that is not a real HTTP server metric, encoding an unrelated domain under the http.server prefix.
- qr-metric-naming (`pkg/telemetry/telemetry.go`): The auth decision counter uses attribute key "error.type" for a denial reason and "outcome" for allowed/denied, but the HTTP metrics use semconv.ErrorTypeKey; mixing a hand-written "error.type" string attribute with the semantic-convention key introduces inconsistent attribute conventions for the same concept.

- qr-preserves-behavior (`pkg/telemetry/telemetry.go`): otelhttp.NewHandler is given the raw serviceName as the operation/span name for every request, producing a single constant span name instead of a per-route name and, more importantly, this hand-rolled otelhttp wrapping inside a chi middleware is not the recommended otelchi integration; combined with the statusRecorder being passed as the ResponseWriter to otelhttp (traced.ServeHTTP(rec, r)) the status code seen by otelhttp's own metrics and the recorder can diverge.
- qr-metric-naming (`pkg/telemetry/telemetry.go`): The new metric name http.server.request.count invents a redundant .count suffix that OTel semconv avoids for counters (semconv uses http.server.request duration/body sizes and unsuffixed counters), and http.server.auth.decisions is not a semantic-convention name; mixing a semconv name (http.server.request.duration) with these ad-hoc siblings is inconsistent.
