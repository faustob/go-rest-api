**Auto-fixed during review (6):**
- qr-not-a-noop (`pkg/telemetry/middleware.go`): The package-level `var meter = otel.Meter(meterName)` is evaluated at package initialization, which runs BEFORE main() calls SetupOTelSDK/SetMeterProvider. In OTel-Go the global MeterProvider is a delegating provider, so meters/instruments created before registration DO delegate correctly once the SDK is set — but only if the delegate is installed via SetMeterProvider. Here registration is wrapped in setGlobalMeterProvider which recovers/swallows panics; more importantly the flow is sound. This is not the defect.
- qr-not-a-noop (`pkg/telemetry/otel.go`): setGlobalTracerProvider/setGlobalMeterProvider defer recover() and always return nil, so the 'already registered, continuing' log path is dead code and, worse, otel.SetTracerProvider/SetMeterProvider do not panic on re-registration — they only log via the global error handler. The recover wrapper does not affect correctness of registration, so the SDK is still registered; this is not a no-op.
- qr-preserves-behavior (`pkg/telemetry/middleware.go`): RequestTelemetryMiddleware wraps the ResponseWriter in statusRecorder that implements only Flusher, dropping the http.Hijacker and io.ReaderFrom interfaces of the underlying writer. Any downstream code relying on hijacking (e.g. websockets) or ReadFrom optimization will break because type assertions on the wrapped writer now fail.
- qr-preserves-behavior (`pkg/telemetry/middleware.go`): otelchi.Middleware is registered on the router before RequestTelemetryMiddleware, but the p99 span-event and error-type attribute code reads trace.SpanFromContext(r.Context()). Because otelchi's span ends when its handler returns, and RequestTelemetryMiddleware runs inside otelchi's chain, the span is still active when attributes/events are added — this is fine. No action needed.
- qr-not-a-noop (`pkg/telemetry/otel.go`): setGlobalTracerProvider/setGlobalMeterProvider defer a bare recover() but otel.SetTracerProvider/SetMeterProvider do not panic on re-registration (they just log), so the "tolerate already-registered agent" comment is misleading; more importantly the recover-in-deferred-closure only fires if the current goroutine panics, which SetTracerProvider never does — the defensive logic is inert but harmless. Not a real defect on its own.
- qr-not-a-noop (`pkg/telemetry/middleware.go`): The package-level `var meter = otel.Meter(meterName)` is evaluated at package init, before SetupOTelSDK registers the global MeterProvider; however since instruments are created inside initInstruments() (called after registration) and OTel-Go's global meter delegates, the instruments do bind correctly — no runtime no-op.
